# Checkpoint 0.40 — CSV 微小差额如实显示、移动端隐私说明可读性

## 变更边界

冻结的单来源 CSV 财务核对规则**没有改变**：以账户基础货币计，`abs(报表值 − 计算值) <= 0.000001` 是数值容差；来源、组成项、模式冲突等其他条件也必须满足。混合 MTM 与 Month/YTD 的跨来源比较仍要求十进制完全相等。`PASS_EXACT` 依冻结文档表示“在 CSV 容差内”，不是数学上的差额必为零；`PASS_ROUNDED` 仍只留给将来有证据的 PDF 对照，不授予当前 CSV Worker 结果。参见 `docs/ACCOUNTING_RECONCILIATION.md` 第 7–8 节。

此前解析器把容差内非零的三项对账差额归零，账本又把状态称作“完全一致”。这不会改变通过/警告的旧判定，却掩盖了来源实际写出的 ±0.000001。现在保留报表值减计算值的**真实有符号差额**，只在状态判断时使用绝对值容差；Worker 边界要求传回的 `reported − calculated − difference` 精确为零，不再允许用容差把伪造的零差额蒙混过去。账本三语状态改为“符合 CSV 容差”，附有方向、绝对值和其他条件的说明；纯虚构 Demo 单独显示“虚构数字相符”，不声称经过 CSV 核对。手机窄屏的隐私说明正文和小标题改为 14px，对账状态徽标改为 12px。

## 验证结果

- 全虚构解析器回归涵盖 MTM、期间盈亏、NAV 衔接的正负 `0.000001`，确认实际差额和符号保留、仍按原规则通过；`0.0000011` 则保持警告。没有用真实客户报表。
- Worker 边界回归拒绝三项“报表值和计算值不同但差额报成零”的伪结果；接受解析器真实的微小差额；拒绝将当前 CSV 的微小差额冒充 PDF 的 `PASS_ROUNDED`。原混合来源的严格比较回归仍在完整套件中。
- 生产版 Chrome 用真实解析 Worker 导入虚构 `+0.000001` MTM CSV；账本显示 `+$0.000001`、“Within CSV tolerance”、“Internal checks passed”和 `Self-reported · not broker-verified`，无错误的 `mtm_difference` 警告。320px 模拟视口检查新徽标至少 12px、无横向裁切。
- 生产版 Chrome 对英语、简体、繁体各在 320×568 与 375×667 共六组验证隐私弹窗：14px 正文、可滚动读到原始 CSV 清理说明的开头与末尾、无横向溢出，顶部关闭和底部确认按钮均可实际点击并恢复焦点。新增断言要求正文至少 13px，因此原 10px 样式不满足。此处是桌面浏览器模拟，不是真机 Safari 或 VoiceOver 实听。
- Node 22 `npm run check`、另行 `npm run build`、`git diff --check` 均退出 0；完整浏览器套件记录 58 次本地请求、36 个 Worker target。构建产物 `index-Cy9qqHzK.js`、`ibkrParser.worker-DH4j2t4Z.js`、`index-CbOMChL0.css`；`npm audit --audit-level=high` 报 0 个漏洞。独立只读复核指出初版说明遗漏“绝对值”和其他条件，修订后复核未发现新的财务回归。
