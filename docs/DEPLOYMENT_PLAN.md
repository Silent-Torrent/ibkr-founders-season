# Vercel 部署审批方案

**审批范围。** 用户已决定解冻并选定 Vercel。建议先批准一次仅项目成员可访问的验收部署。公开生产域名由用户在验收后另行决定。R03 在本方案获批并记录权限范围后关闭。

**套餐与域名。** 个人非商业测试选 Hobby，使用平台分配的 `vercel.app` 域名。商业使用或需要付费功能时，另审 Pro 与预算。[Hobby 适用条件](https://vercel.com/docs/plans/hobby)

**授权与可见性。** 优先使用已有空项目，先在控制台开启 Vercel Authentication，范围选 All Deployments，覆盖预览和生产域名，关闭公开例外、分享绕过链接和工具栏注入。项目曾在首次上传时直接生成生产地址；如果无法事先保护全部域名，就停在上传前。GitHub 如需连接，只选 `Silent-Torrent/ibkr-founders-season` 一个仓库，核对安装权限。保留手动发布，Git 推送只触发检查。验收者须用获准的 Vercel 账号登录。[全域名保护说明](https://vercel.com/changelog/protect-production-deployments-for-free-on-every-plan)

**首次上传前。** 记录候选提交。用 Node 22、锁定依赖执行 `npm ci` 和 `npm run build`，确认 GitHub Actions 对相同代码的完整 `npm run check` 通过，包括保留沙箱的 Chrome 导入、Worker 和图片测试；高危依赖审计通过。核对上传清单，只发布静态产物 `dist`，测试仅用仓库虚构样本。关闭平台分析和注入功能。记录部署编号及域名，立即用未登录窗口验证所有域名都要求认证。

**R01 · 登录后验隐私。** 用干净浏览器打开开发者工具，记录网络、存储和响应头。访问首页和子路径，导入虚构 CSV、查看账本、导出 PNG、刷新。确认应用只请求本站静态文件，无报表上传或第三方请求；核对存储白名单，仅保留语言、引导、文案、涨跌颜色、拉面单价、分享选项及首次创始赛季导入月份，刷新后回到演示数据。区分平台登录状态与应用存储。检查 HTML、脚本、样式和 Worker 的类型、CSP、禁止嵌入、HSTS、nosniff、来源及权限策略。记录提交、域名和结果，证据去除认证信息。

**R02 · 用 iPhone 验分享。** 在受保护的 HTTPS 地址用 Safari 导入虚构样本，调用系统分享并存入“文件”。找到并重新打开 `pnl-arena-2026-season.png`，核对完整文件名、1200×1500 尺寸和卡片内容。记录机型、系统、提交与结果，清理测试副本。

**公开与回滚。** R01、R02 及其余产品门禁须有关闭证据，用户批准后才开放生产域名。若发现数据外传、匿名可见或核心功能失效，立即保护全部域名并验证匿名访问被拒。已有合格生产版本时，在 Vercel 选择上一版执行 Instant Rollback，复查域名、响应头和虚构导入。首次发布若无可回滚版本，则保持封闭并撤下故障部署，核查各地址均不可公开访问。修复后按新提交重新验收。[回滚说明](https://vercel.com/docs/instant-rollback)
