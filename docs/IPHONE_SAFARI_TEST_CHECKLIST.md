# iPhone Safari 真机测试清单（只用虚构 CSV）

## 这份清单的作用

这是可重复使用的真实 iPhone 操作清单，本身不是“全部已通过”证明。

2026-09-02 checkpoint 0.15 已在 iPhone 17 Pro Max / iOS 27.0 系统 Safari 完成更完整的全虚构真机闭环：三语隐私弹窗、系统文件选择、控制 CSV 导入、刷新与关标签清除、精确容量、可视取消、自然超时、两种超限后保留旧报表，以及导入报表 PNG 存入 Files 后重开和 1200×1500 尺寸均已观察通过。精确范围、限制和未验证项见 `docs/IPHONE_SAFARI_EVIDENCE_2026-09-02.md`。仍未验证 iOS/Safari 16.4 最低版本、横竖屏、峰值内存、HTTPS 原生分享及精确文件名、完整 VoiceOver 语音/焦点顺序、部署后的 Network/Storage 检查和真实 Exercise 行。

最低支持决定是 iOS 16.4+ / Safari 16.4+，但测试对象必须是 `npm run build` 生成的生产版本（例如受保护的 Preview），不能用 Vite 开发服务器代替。新版 Safari 或当前 WebKit 通过，也不能证明 16.4 最低版本已经通过；若没有 16.4 设备、模拟器或云真机，就如实记录为“版本下限未验证”。

## 最重要的安全规则

1. 普通功能测试只能使用项目自带的全虚构文件：`tests/fixtures/ibkr-current-schema-synthetic.csv`。容量/取消测试只能使用开发方通过 `docs/IPHONE_STRESS_TEST_PACK.md` 所述工具生成、独立校验并提供 SHA-256 清单的全虚构边界文件；不得自行改大文件或用真实报表替代。
2. 不要把自己的 IBKR CSV、PDF、账户号、持仓或截图传到手机测试站点。
3. 不要输入 IBKR 用户名、密码、PIN、2FA 验证码或交易授权。当前应用根本不需要这些信息。
4. 正式托管地址如果跳转到陌生网址、要求登录/付款、显示证书警告，或出现任何真实金融数据，立即停止并告诉我们。若开发方明确安排“同一可信 Wi-Fi 下的临时局域网测试”，地址会是开发方当场给出的 `http://` 数字 IP，Safari 可能标成“不安全”；这只是短时、无传输加密的功能测试，只能使用全虚构数据，不代表正式部署安全性已经通过。
5. 测试期间的截图只能包含虚构数据。

## F. 赛季卡 PNG 下载

1. 再次导入虚构 CSV。
2. 在“盈亏账本”页找到赛季战绩卡，点击“下载 PNG”。
3. 在 HTTPS 且浏览器支持文件分享时，系统可能直接打开分享面板；同一 Wi-Fi 的临时 HTTP 测试会先显示“本机 PNG 预览”。
