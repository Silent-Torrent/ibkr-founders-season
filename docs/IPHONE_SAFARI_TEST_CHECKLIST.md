# iPhone Safari 真机测试清单（只用虚构 CSV）

## 这份清单的作用

这是可重复使用的真实 iPhone 操作清单，本身不是“全部已通过”证明。

2026-09-02 checkpoint 0.15 已在 iPhone 17 Pro Max / iOS 27.0 系统 Safari 完成更完整的全虚构真机闭环：三语隐私弹窗、系统文件选择、控制 CSV 导入、刷新与关标签清除、精确容量、可视取消、自然超时、两种超限后保留旧报表，以及导入报表 PNG 存入 Files 后重开和 1200×1500 尺寸均已观察通过。精确范围、限制和未验证项见 `docs/IPHONE_SAFARI_EVIDENCE_2026-09-02.md`。仍未验证 iOS/Safari 16.4 最低版本、横竖屏、峰值内存、HTTPS 原生分享及精确文件名、完整 VoiceOver 语音/焦点顺序、部署后的 Network/Storage 检查和真实 Exercise 行。

最低支持决定是 iOS 16.4+ / Safari 16.4+，但测试对象必须是 `npm run build` 生成的生产版本（例如受保护的 Preview），不能用 Vite 开发服务器代替。新版 Safari 或当前 WebKit 通过，也不能证明 16.4 最低版本已经通过；若没有 16.4 设备、模拟器或云真机，就如实记录为“版本下限未验证”。

## 最重要的安全规则

1. 普通功能测试只能使用项目自带的全虚构文件：`tests/fixtures/ibkr-current-schema-synthetic.csv`。容量/取消测试只能使用开发方通过 `docs/IPHONE_STRESS_TEST_PACK.md` 所述工具生成、独立校验并提供 SHA-256 清单的全虚构边界文件；不得自行改大文件或用真实报表替代。
2. 不要把自己的 IBKR CSV、PDF、账户号、持仓或截图传到手机测试站点。
3. 不要输入 IBKR 用户名、密码、PIN、2FA 验证码或交易授权。当前应用根本不需要这些信息。
4. 正式托管地址如果跳转到陌生网址、要求登录/付款、显示证书警告，或出现任何真实金融数据，立即停止并告诉我们。若开发方明确安排“同一可信 Wi-Fi 下的临时局域网测试”，地址会是开发方当场给出的 `http://` 数字 IP，Safari 可能标成“不安全”；这只是短时、无传输加密的功能测试，只能使用全虚构数据，不代表正式部署安全性已经通过。
5. 测试期间的截图只能包含虚构数据。

## D. 取消和超时

1. 先按 `docs/IPHONE_STRESS_TEST_PACK.md` 完成 Mac 上的包校验，再把完整包传到 iPhone。不要手工修改任何大 CSV。
2. 用 `00-control-small.csv` 完成小文件基准后，在新标签页导入 `01-accepted-exact-capacity.csv`，记录是否成功显示 500 行，以及是否出现空白、崩溃或标签页自行重载。

4. 正常小文件不应触发 12 秒超时。开发电脑上的生产版 Chrome 已用全虚构边界文件通过可见取消和 Worker 终止测试，但这不等于 iPhone 已通过。若 `02` 在点击前已完成，取消记为 `NOT_EXERCISED`，不是通过。没有 Safari Web Inspector 证据时，不能声称直接观察到 Worker 终止。
5. 再在新标签页导入 `02`，这次不取消。若 12 秒内成功，超时仍是 `NOT_TRIGGERED`；只有生产页面自然显示固定超时，才能记录已观察。

### 下次真机实听的操作顺序（执行前全部记为 `NOT_RUN`）

开发方先记录本次生产构建的提交号/资产、测试地址是局域网 HTTP 还是获准 HTTPS、iPhone 型号、iOS 精确版本、可核实的 Safari 版本、界面语言和日期，并确认手机**实际打开**该构建；Mac 本地页面打开不算手机通过。若 Safari 独立版本无法核实，记录“系统 Safari，独立版本未核实”，不猜数字。先核对 VoiceOver 原始开关、网页原始语言与网络，和用户约定结束后恢复什么。只用上方已说明的全虚构 CSV；需要错误或进行中取消时，使用开发方按 `docs/IPHONE_STRESS_TEST_PACK.md` 独立校验过的虚构压力包，其中 `03-reject-501-symbols.csv` 用于拒绝，`02-cancel-timeout-probe.csv` 用于取消。没有已校验的包就把相应步骤记为 `NOT_RUN`，不要临时用真实报表或自编大文件代替。既有临时 VoiceOver/实听授权已取得，本轮确认用户仍可配合实际听取，由开发方陪同操作和记录；镜像画面、桌面辅助功能树、成功提示的可见文字均不能代替手机播报。

1. 打开生产页，临时开启 VoiceOver 并核对开关为 On。按 English、简体中文、繁體中文逐一检查底部四个导航入口、当前入口、语言选择和导入页“选择 CSV 文件”的名称；用户说出实际听到的大意和顺序，开发方记焦点所在控件及是否能启动操作。若切换语言会离开正在做的导入流程，先完成该语言步骤，再切换。未走到的语言保持 `NOT_RUN`。
2. 在每种语言从可辨认的入口打开“隐私与数据详情”。检查焦点是否进入弹窗、标题和说明文字能否顺序读出、顶部关闭与底部确认按钮能否找到；继续向前/向后移动到边界，确认不会读到或激活背后的导航/语言按钮。分别通过关闭按钮和底部确认按钮关闭并核对焦点返回本次打开入口；必要时重新打开。若测试背景关闭，另记可见结果，**不能**据此推断 VoiceOver 焦点隔离或回焦通过。
3. 到导入页先点“选择 CSV 文件”，在 iOS 原生“文件”选择器中不选文件、直接关闭。确认返回网页后选择入口仍可用、没有把这次操作报成“已取消导入”。这是**文件选择器取消**；它与下方“解析进行中点击取消导入”是两条不同路径。
4. 优先选择已校验压力包的 `00-control-small.csv`，等待导入成功并切到虚构账本；若暂时没有该包，可用本地预览提供的 `public/sample-ibkr-ytd.csv` 仅做成功播报检查，步骤 5–6 仍须用已校验压力包，否则记 `NOT_RUN`。用户复述实际听到的进行中与成功通知（若没听到也如实记下），检查焦点到达何处、是否能继续导航；开发方目视核对 `Fully synthetic test`/对应译文及旧数据替换状态。若同一快照被判重复，不把重复提示当成功通知：先在新标签从 Demo 重做，或记 `NOT_TRIGGERED`。
5. 保留一份已接受的虚构账本，返回导入页选择已校验的 `03-reject-501-symbols.csv`。用户复述错误、恢复提示与“重新选择”的实际播报；开发方核对错误可见。先用仍显示的“重新选择”打开并关闭原生选择器，确认入口可继续使用；然后返回账本核对原有虚构来源、赛季盈亏和标的仍在。单看来源徽标不足以证明整个旧账本保留。
6. 在独立的 Demo 新标签选择已校验的 `02-cancel-timeout-probe.csv`；只有页面确实出现“取消导入”时才激活它。用户复述进行中、取消和重试入口的实际播报，记录取消前后焦点、能否继续操作；等待至少 12.25 秒，核对没有迟到的新报表。若文件已先完成或自然超时，记 `NOT_TRIGGERED`，不冒充进行中取消通过。文件选择器直接关闭也不能替代这一步。
7. 回到前面已接受虚构报表的标签，在账本分享区打开“手动选择文字”/对应译文，检查入口、区域标题、只读摘要框、选择文字按钮、说明及关闭按钮的名称和焦点顺序；关闭后核对焦点返回手选入口且仍可操作。这里验证可感知性与焦点，不要求复制到系统剪贴板；若另做原生复制，先按当次约定处理剪贴板和临时粘贴内容。
8. 完成后把 VoiceOver 切回原状态并**重新读回开关**，恢复原网页语言、输入法和任何当次获准临时网络；关闭仅本次确认的测试标签、停止仅本次启动的本地服务并核对端口。若向手机新增了虚构 CSV，只定位本次确切文件并按约定移到可恢复的“最近删除”，记录是否仍有另存副本；不要盲删旧 Photos 卡、清空整个下载目录或永久清空“最近删除”。页面清空不等于清空系统剪贴板。若某项恢复或清理未完成，单独记为开放事项。
