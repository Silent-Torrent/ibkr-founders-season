# iPhone Safari 真机测试清单（只用虚构 CSV）

## 这份清单的作用

这是可重复使用的真实 iPhone 操作清单，本身不是“全部已通过”证明。

2026-09-01 已在 iPhone 17 Pro Max / iOS 27.0 Safari 完成一次部分真机闭环：页面、语言、系统文件选择、全虚构 CSV 导入、刷新清除和导入报表的本机 PNG 预览通过；Safari 分享及“我的 iPhone”保存重开只用演示卡完成，尚不能证明导入报表卡的保存往返。精确范围、限制和未验证项见 `docs/IPHONE_SAFARI_EVIDENCE_2026-09-01.md`。VoiceOver、真机取消/超时、边界容量、横竖屏、隐私弹窗和 iOS/Safari 16.4 最低版本仍未通过。

最低支持决定是 iOS 16.4+ / Safari 16.4+，但测试对象必须是 `npm run build` 生成的生产版本（例如受保护的 Preview），不能用 Vite 开发服务器代替。新版 Safari 或当前 WebKit 通过，也不能证明 16.4 最低版本已经通过；若没有 16.4 设备、模拟器或云真机，就如实记录为“版本下限未验证”。

## 最重要的安全规则

1. 普通功能测试只能使用项目自带的全虚构文件：`tests/fixtures/ibkr-current-schema-synthetic.csv`。容量/取消测试只能使用开发方通过 `docs/IPHONE_STRESS_TEST_PACK.md` 所述工具生成、独立校验并提供 SHA-256 清单的全虚构边界文件；不得自行改大文件或用真实报表替代。
2. 不要把自己的 IBKR CSV、PDF、账户号、持仓或截图传到手机测试站点。
3. 不要输入 IBKR 用户名、密码、PIN、2FA 验证码或交易授权。当前应用根本不需要这些信息。
4. 正式托管地址如果跳转到陌生网址、要求登录/付款、显示证书警告，或出现任何真实金融数据，立即停止并告诉我们。若开发方明确安排“同一可信 Wi-Fi 下的临时局域网测试”，地址会是开发方当场给出的 `http://` 数字 IP，Safari 可能标成“不安全”；这只是短时、无传输加密的功能测试，只能使用全虚构数据，不代表正式部署安全性已经通过。
5. 测试期间的截图只能包含虚构数据。

## 开始前需要准备什么

- [ ] 由开发方提供一个明确的测试地址。项目尚未部署时，不要自己搜索或猜测网址。局域网测试只接受开发方当场给出的数字 IP，并确认手机与 Mac 连接同一个可信家庭 Wi-Fi。
- [ ] 开发方将上述虚构 CSV 通过 AirDrop 或 iCloud Drive 放入 iPhone 的“文件”App。
- [ ] 在“文件”App 中确认文件名正好是 `ibkr-current-schema-synthetic.csv`。
- [ ] 记录 iPhone 型号、iOS 精确版本和测试日期。iPhone 上的 Safari 随 iOS 更新，不会查时先告诉开发方，不必自己猜。

## C. 导入虚构 CSV

2. 点击“选择 CSV 文件”。
3. Safari 打开文件选择器后，选择 `ibkr-current-schema-synthetic.csv`。
4. 等待页面自动返回“盈亏账本”，并确认顶部显示“全虚构测试”，而不是“用户自报”或“演示数据”。
5. 这份虚构文件的预期结果为：

   - 正股年度盈亏：167.622477 USD

## D. 取消和超时

1. 先按 `docs/IPHONE_STRESS_TEST_PACK.md` 完成 Mac 上的包校验，再把完整包传到 iPhone。不要手工修改任何大 CSV。
2. 用 `00-control-small.csv` 完成小文件基准后，在新标签页导入 `01-accepted-exact-capacity.csv`，记录是否成功显示 500 行，以及是否出现空白、崩溃或标签页自行重载。
3. 在另一个新标签页选择 `02-cancel-timeout-probe.csv`。如果“取消导入”按钮可见，立即点击；看到取消提示后继续等待至少 12.25 秒，确认没有迟到的新报表。
4. 正常小文件不应触发 12 秒超时。开发电脑上的生产版 Chrome 已用全虚构边界文件通过可见取消和 Worker 终止测试，但这不等于 iPhone 已通过。若 `02` 在点击前已完成，取消记为 `NOT_EXERCISED`，不是通过。没有 Safari Web Inspector 证据时，不能声称直接观察到 Worker 终止。
5. 再在新标签页导入 `02`，这次不取消。若 12 秒内成功，超时仍是 `NOT_TRIGGERED`；只有生产页面自然显示固定超时，才能记录已观察。
6. 保留 `01` 的已接受报表，分别导入 `03-reject-501-symbols.csv` 和 `04-reject-1001-events.csv`；两者都应容量拒绝，并不覆盖旧的 500 行报表。
7. 手工真机只能记录“未观察到崩溃/重载”，不能写成 Worker 峰值内存已测量。

记录：

- [ ] 精确容量导入已观察
- [ ] 取消与无迟到结果已观察
- [ ] 取消 `NOT_EXERCISED`
- [ ] 超时已自然触发并观察
- [ ] 超时 `NOT_TRIGGERED`
- [ ] 501 标的/1,001 事件失败关闭已观察
- [ ] 出现异常，已停止测试

## E. 刷新和关闭后清除

1. 在虚构报表已导入的状态下，点击 Safari 的刷新按钮。
2. 确认页面回到“演示数据”，而不是恢复刚才的“全虚构测试”。
3. 再次导入虚构 CSV，然后关闭该 Safari 标签页。
4. 重新打开测试地址，确认仍是“演示数据”。
5. 语言可以保留，因为语言是当前唯一允许持久保存的非财务偏好。

## F. 赛季卡 PNG 下载

1. 再次导入虚构 CSV。
2. 在“盈亏账本”页找到赛季战绩卡，点击“下载 PNG”。
3. 在 HTTPS 且浏览器支持文件分享时，系统可能直接打开分享面板；同一 Wi-Fi 的临时 HTTP 测试会先显示“本机 PNG 预览”。
4. 出现本机预览时，先确认卡片完整，再点击“在 Safari 中打开 PNG”。新标签页可能短暂显示空白，等待约一秒；不要连续反复点击。
5. 在原始 PNG 标签页点击 Safari 分享按钮，选择“存储到文件”。局域网 HTTP 回退可能使用系统随机文件名；正式 HTTPS 分支的指定文件名仍需另测。
6. 打开保存后的 PNG，确认不是空白图，数字、文字没有被截断；文件信息应为 PNG、`1200 × 1500`。
7. 确认 PNG 不包含底层标的代码、账户标识或精确净清算价值；如果显示资产组别，它仍可能透露一个宽泛的美元余额区间。
8. 这张 PNG 是独立下载文件；刷新或清除网页不会删除它。测试结束后如不需要，请在“文件”或下载位置手动删除。

这一部分必须在真机上单独测试。如果你不熟悉 VoiceOver，不要独自开启，之后让开发方陪同操作，因为开启后手机的点按方式会改变。

## 发现问题时怎么记录

每个问题只记录下面五项，不需要技术术语：

1. 手机型号和 iOS 版本。
2. 当时在哪个页面。
3. 按了什么。
4. 期望发生什么，实际发生了什么。
5. 一张只含虚构数据的截图（如果能拍）。

请不要因为“应该没事”而勾选“通过”。只有在真实 iPhone 上完成对应步骤后，才能将该项记为通过。
