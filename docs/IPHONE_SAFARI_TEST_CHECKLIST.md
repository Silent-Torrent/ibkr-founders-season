# iPhone Safari 真机测试清单（只用虚构 CSV）

## 这份清单的作用

这是之后在真实 iPhone 上做测试时的操作清单，不是“已通过”证明。

当前只确认了电脑浏览器中的键盘/焦点行为和 320 px 模拟窄屏。真实 iPhone Safari、VoiceOver、真机取消/超时和 PNG 下载都还没有通过验证。

最低支持决定是 iOS 16.4+ / Safari 16.4+，但测试对象必须是 `npm run build` 生成的生产版本（例如受保护的 Preview），不能用 Vite 开发服务器代替。新版 Safari 或当前 WebKit 通过，也不能证明 16.4 最低版本已经通过；若没有 16.4 设备、模拟器或云真机，就如实记录为“版本下限未验证”。

## 最重要的安全规则

1. 普通功能测试只能使用项目自带的全虚构文件：`tests/fixtures/ibkr-current-schema-synthetic.csv`。容量/取消测试只能使用开发方另行生成并提供 SHA-256 清单的全虚构边界文件；不得自行改大文件或用真实报表替代。
2. 不要把自己的 IBKR CSV、PDF、账户号、持仓或截图传到手机测试站点。
3. 不要输入 IBKR 用户名、密码、PIN、2FA 验证码或交易授权。当前应用根本不需要这些信息。
4. 如果页面跳转到陌生网址、要求登录/付款、显示“连接不安全”，或出现任何真实金融数据，立即停止并告诉我们。
5. 测试期间的截图只能包含虚构数据。

## 开始前需要准备什么

- [ ] 由开发方提供一个明确的测试地址。项目尚未部署时，不要自己搜索或猜测网址。
- [ ] 开发方将上述虚构 CSV 通过 AirDrop 或 iCloud Drive 放入 iPhone 的“文件”App。
- [ ] 在“文件”App 中确认文件名正好是 `ibkr-current-schema-synthetic.csv`。
- [ ] 记录 iPhone 型号、iOS 精确版本和测试日期。iPhone 上的 Safari 随 iOS 更新，不会查时先告诉开发方，不必自己猜。
- [ ] 确认用 Safari 打开，不是微信、邮件或其他 App 内置的网页。

## A. 打开页面和基本显示

1. 在 Safari 地址栏输入开发方给出的测试地址。
2. 确认首页可以正常显示，文字没有被截断，页面可以上下滑动。
3. 分别点击底部的“盈亏账本/競技场/勋章/导入”，确认四个入口都可以打开。
4. 把手机旋转为横屏，再转回竖屏，确认页面没有卡住、空白或严重重叠。

记录：

- [ ] 通过
- [ ] 未通过
- [ ] 暂时无法测试

## B. 三种语言和隐私说明

1. 使用页面右上角的语言选择，依次切换 English、简体中文、繁體中文。
2. 每切换一种语言，都从页脚点击“隐私与数据详情”或对应译文。
3. 确认隐私说明可以上下滑动，标题和关闭按钮始终可用。
4. 确认内容明确说明：本地解析、不上传、只在当前标签页保留、仅语言偏好可持久化、不验证报表真伪、PDF 当前不解析、不构成投资建议、如何清除数据。
5. 分别用右上角“×”、底部“我知道了”和点击弹窗外的深色背景关闭弹窗。

记录：

- [ ] 通过
- [ ] 未通过
- [ ] 暂时无法测试

## C. 导入虚构 CSV

1. 点击底部“导入”。
2. 点击“选择 CSV 文件”。
3. Safari 打开文件选择器后，选择 `ibkr-current-schema-synthetic.csv`。
4. 等待页面自动返回“盈亏账本”，并确认顶部显示“全虚构测试”，而不是“用户自报”或“演示数据”。
5. 这份虚构文件的预期结果为：
   - 赛季盈亏：740.123456 USD
   - 正股年度盈亏：167.622477 USD
   - 期权年度盈亏：450.222223 USD
   - 其他年度盈亏：122.278756 USD
   - 三个底层标的
   - 两个期权事件
   - 三项对账检查都显示完全一致
6. 打开“竞技场”，确认这份测试结果没有进入排名，也没有出现个人名次。
7. 打开“勋章”，确认虚构测试数据没有解锁“本机成就”。
8. 点开第一个底层标的，确认详情抽屉可以滑动、规范化来源引用卡可以展开，并且可以关闭（应不显示原始行或原始数值）。

## D. 取消和超时

1. 再次进入“导入”，选择同一份虚构 CSV。
2. 如果“取消导入”按钮足够长时间地出现，立即点击，确认页面没有卡死或显示已取消文件的新结果。
3. 这份测试 CSV 通常解析很快。如果看不到取消按钮，记录为“暂时无法测试”，不要反复乱点，也不要改大文件。
4. 正常小文件不应触发 12 秒超时。开发电脑上的生产版 Chrome 已用临时全虚构边界文件通过可见取消和 Worker 终止测试，但这不等于 iPhone 已通过。真机取消与超时仍必须由开发方另行准备带 SHA-256 清单的全虚构慢速/边界文件；不得用真实报表代替。

- [ ] 取消暂时无法测试
- [ ] 超时暂时无法测试
- [ ] 出现异常，已停止测试

## E. 刷新和关闭后清除

1. 在虚构报表已导入的状态下，点击 Safari 的刷新按钮。
2. 确认页面回到“演示数据”，而不是恢复刚才的“全虚构测试”。
3. 再次导入虚构 CSV，然后关闭该 Safari 标签页。
4. 重新打开测试地址，确认仍是“演示数据”。
5. 语言可以保留，因为语言是当前唯一允许持久保存的非财务偏好。

## F. 赛季卡 PNG 下载

1. 再次导入虚构 CSV。
2. 在“盈亏账本”页找到赛季战绩卡，点击“下载 PNG”。
3. 如果 Safari 打开图片预览、下载面板或分享面板，记录实际显示的内容，不要随意上传到公开社交平台。
4. 打开保存后的 PNG，确认不是空白图，数字、文字没有被截断。
5. 确认 PNG 不包含底层标的代码、账户标识或精确净清算价值；如果显示资产组别，它仍可能透露一个宽泛的美元余额区间。
6. 这张 PNG 是独立下载文件；刷新或清除网页不会删除它。测试结束后如不需要，请在“文件”或下载位置手动删除。

## G. VoiceOver（尚未验证）

这一部分必须在真机上单独测试。如果你不熟悉 VoiceOver，不要独自开启，之后让开发方陪同操作，因为开启后手机的点按方式会改变。

需要验证的项目：

- [ ] 底部导航、语言选择和导入按钮名称可被正确读出。
- [ ] 打开隐私弹窗后，VoiceOver 焦点进入弹窗，不会跑到后面的页面。
- [ ] 弹窗标题、正文、关闭按钮和“我知道了”可被按合理顺序读出。
- [ ] 关闭弹窗后，焦点返回打开弹窗的入口。
- [ ] 导入成功、错误和取消状态能被感知。

## 发现问题时怎么记录

每个问题只记录下面五项，不需要技术术语：

1. 手机型号和 iOS 版本。
2. 当时在哪个页面。
3. 按了什么。
4. 期望发生什么，实际发生了什么。
5. 一张只含虚构数据的截图（如果能拍）。

请不要因为“应该没事”而勾选“通过”。只有在真实 iPhone 上完成对应步骤后，才能将该项记为通过。
