# iPhone Safari 真机证据（2026-09-01）

## 结论

本轮在真实 iPhone Safari 上完成了**部分真机闭环**：生产构建页面、三种语言、系统文件选择器、Web Worker 导入、刷新后清除、虚构数据不排名/不授勋、本机 PNG 预览、Safari 系统分享、保存到“我的 iPhone”以及保存文件重开均通过。

这不是完整发布门槛。iOS 16.4 / Safari 16.4 最低版本、VoiceOver、横竖屏、隐私弹窗、标的详情抽屉、真机取消/超时、边界容量、峰值内存、HTTPS 托管、部署响应头、剪贴板和真机 Network/Storage 检查仍未完成。

## 测试边界

- 日期：2026-09-01（Asia/Shanghai）
- 设备：iPhone 17 Pro Max
- 系统：iOS 27.0；Safari 随系统版本提供
- 页面：当次 `npm run build` 生成的生产包，由 Mac 临时绑定其可信家庭 Wi-Fi IPv4 的 Vite Preview 提供
- 传输：同一可信 Wi-Fi 下的临时 `http://<Mac Wi-Fi IPv4>:4173`，无 HTTPS
- 输入：仅项目自带的全虚构 `tests/fixtures/ibkr-current-schema-synthetic.csv`
- 输入 SHA-256：`80831483527003e501aa63f1691a2f155a37b8279f68e2e3e31cb244a219d7ff`
- 未把用户真实 IBKR CSV/PDF、账户标识、密码、验证码或交易授权送入手机测试页
- 测试期间保持外部部署冻结；本轮没有创建公网域名或云部署

局域网 HTTP 私有 IP 不是安全上下文。Web Share API 的 `share()` / `canShare()` 要求安全上下文，因此本轮不能把“原生文件分享分支未出现”判断为 PNG 构造错误；参考 [Web Share API](https://www.w3.org/TR/web-share/#api-definition) 和 [Secure Contexts](https://www.w3.org/TR/secure-contexts/#is-origin-trustworthy)。正式 HTTPS 环境仍需单独验证原生分享与指定文件名。

## 本轮发现并修正的 PNG 问题

1. 旧实现使用脱离文档的 `<a download>` 和 Canvas `data:` URL。iOS Safari 点击后没有文件落盘。
2. 改成自动点击 Blob 下载链接仍未在“文件”中找到结果，不能计为通过。
3. 最终实现保留桌面下载和 iOS 安全上下文中的 Web Share；在 iOS 且文件分享不可用时，改为显示真实的本机 Blob 图片预览和明确的“在 Safari 中打开 PNG”入口。
4. 新标签页初次显示短暂空白，约一秒后图片加载；源网页标签页保持打开，随后 Safari 系统分享和“存储到文件”成功。
5. 自动回归现已覆盖：桌面下载回退、Web Share 文件名/MIME/字节、iOS Blob 预览的生成与焦点、切换语言或清除报表时隐藏预览并释放 Blob URL，以及 PNG 隐私禁项。

## 尚未验证，不能宣称通过

- iOS 16.4 / Safari 16.4 最低支持版本；本轮只证明 iOS 27.0 的观察结果。
- VoiceOver 的读出顺序、弹窗焦点圈定、关闭后焦点返回和状态播报。
- 隐私弹窗在真机上的三种关闭方式及完整滚动。
- 标的详情抽屉和规范化来源引用卡的真机操作。
- 横屏与竖屏往返。
- 普通小文件解析太快，未观察到可点击的真机取消按钮；12 秒超时也未触发。
- 5 MiB / 100,000 行边界文件在 iPhone 上的耗时、峰值内存和 Worker 回收。
- HTTPS、正式托管身份验证、部署安全响应头、剪贴板和真机网络/存储面板。
- 关闭标签页后重新打开的独立清除步骤；本轮完成的是刷新/重新载入地址后的清除。
- iCloud Drive / Desktop 的 PNG 保存结果未稳定出现在最近项目中；本轮可重复确认的是“我的 iPhone”本地保存。

## 现场遗留

- “我的 iPhone”根目录保留了一张系统随机命名的全虚构演示 PNG，便于用户复看；它是独立文件，不会随网页刷新自动删除。
- Mac 上的局域网预览/附件服务已停止，端口 4173/4174 已确认无监听。
- 为测试创建的 iCloud 网页快捷方式和全虚构 CSV 副本已删除；仓库原始 fixture 未修改。
