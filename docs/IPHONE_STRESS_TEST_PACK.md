# iPhone Safari 全虚构压力测试包

## 作用和非声明

这套工具为真实 iPhone Safari 生成可重复的全虚构 CSV 压力包。生成成功、SHA-256 匹配和 Mac 自动测试通过都不代表真机已通过；认证包内的结果模板永久保持原始 `NOT_RUN`，实际设备观察另存包外，不能直接修改已认证模板。

工具不读取私密测试资料、真实 IBKR CSV/PDF、账户号或持仓。它只使用仓库已有的小型全虚构 fixture 和 `scripts/synthetic-capacity-statement.mjs` 中的确定性生成器。

## 生成安全边界

`prepare:iphone-stress-pack` 强制以下规则：

- 输出路径必须是用户明确给出的绝对路径。
- 输出目录必须在 Git 仓库外。
- 面向真机的命令只接受干净、已提交的 Git 工作区；自动测试使用显式的内部例外，但生成物会如实记录为 `dirty`，不能当作交付包。
- 输出目录必须尚不存在；工具不覆盖或合并现有目录。
- 输出目录的父目录必须已存在，且不能是符号链接。
- 所有文件先写入同一父目录下的随机 staging 目录。
- staging 通过独立校验后，工具才会独占创建最终目录，并以不覆盖的硬链接发布每个文件；完成标记只在全部文件就位后移除。最终发布不会替换并发出现的同名目录或链接。
- 正常的生成、写入或校验失败只清理本次创建且文件身份仍匹配的内容。强制结束进程、系统崩溃或断电仍可能留下隐藏 staging 或带未完成标记的目录；这种目录不能通过校验，应先人工确认路径再删除或改名。

例如，先用 Finder 建立仓库外的父目录 `临时真机测试`。这台 Mac 的系统默认 Node 25 已损坏，因此每次打开新“终端”窗口后，先执行前两行并确认版本显示为 22.12 或更高的 22.x，再生成测试包：

```bash
export PATH="/opt/homebrew/opt/node@22/bin:$PATH"
node --version
npm run prepare:iphone-stress-pack -- "/absolute/path/outside-repo/iphone-stress-pack-2026-09-02"
```

上述最终目录已存在时，命令会失败，不会替换它。本仓库的完整自动检查只在系统临时目录生成、验证并删除测试包；它不会创建桌面真机包。

## 传输前独立校验

生成器在发布前已调用同一独立校验器。AirDrop 或复制到 iPhone 前，再以精确的绝对路径复核一次：

```bash
npm run verify:iphone-stress-pack -- "/absolute/path/outside-repo/iphone-stress-pack-2026-09-02"
```

校验器会在读取前限制文件尺寸，并拒绝相对路径、仓库内路径、多余/缺失文件、符号链接、修改后的字节/行数/SHA-256、非 ASCII CSV、缺失虚构账户标记、真实账户形态或本机路径痕迹、伪造或不可复现的生成来源、非 `NOT_RUN` 初始模板或被改动的安全说明。

## UI 标签的重要限制

只有 `00-control-small.csv` 的确切哈希在应用的已知虚构 fixture 名单中。`01` 和 `02` 虽然也是开发方确定性生成的全虚构数据，但导入后 UI 会保守地显示 `Self-Reported`。这不是文件来自真实账户的证据，也不应为了本测试而扩展 `KNOWN_SYNTHETIC_STATEMENTS`。

`03` 和 `04` 必须失败关闭，不会生成新报表。

## 真机操作和验收

### 00：小文件控制组

1. 在系统 Safari 打开开发方当场提供的生产构建地址。
2. 导入 `00-control-small.csv`。
3. 确认自动返回 Ledger，显示“全虚构测试”、3 个标的、2 个事件和三项精确对账。

### 01：精确上限接受

1. 在新标签页导入 `01-accepted-exact-capacity.csv`，开始计时。
2. 记录导入是否在 12 秒 Worker 上限内完成，以及是否发生空白、崩溃或标签页自行重载。
3. 成功后确认 500 行，搜索 `CAP499`，打开抽屉并确认 Assignment/Exercise/Expiration 为 `1 / 0 / 1`。
4. 滑动和切换页面，观察完成后的基本交互是否仍可用。

这只能证明记录设备在该次负载下没有可见崩溃。它不提供 Worker 峰值内存数值，也不能证明其他 iPhone 或 iOS 16.4。

### 02：取消

1. 在新标签页选择 `02-cancel-timeout-probe.csv`。
2. 文件选择器返回后，若“取消导入”可见，立即点击。
3. 确认出现取消提示，然后继续等待至少 12.25 秒，确认页面没有被迟到的 Worker 结果切换到 Ledger。
4. 在同一未刷新标签页，从取消面板“重新选择”导入 `00` 并成功显示 3 标的账本，才能另外记录恢复通过。该流程从 Demo 开始，不先加载相同 `00`，以免正确的重复报表保护被误判为恢复失败。

如果文件在点击前已完成，记为 `NOT_EXERCISED`，不是通过。没有 Safari Web Inspector 证据时，只能声称取消提示和无迟到结果被观察，不能声称直接观察到 Worker 终止。

### 02：自然超时

1. 在另一个新标签页再次选择 `02`，这次不取消。
2. 若成功完成，记录耗时，但超时路径必须保持 `NOT_TRIGGERED`。
3. 只有未修改的生产页面自然显示固定 12 秒超时，且继续等待后没有迟到结果，才能记录真机超时界面与迟到保护已观察。
4. 若自然超时被触发，在同一未刷新标签页从错误面板“重新选择”导入 `00` 成功，才另外记录超时后恢复通过；未触发则保持 `NOT_TRIGGERED`。

不保证任何合规 CSV 在指定 iPhone 上一定超过 12 秒。为 Worker 加人工延迟或缩短时间只能证明专用 QA 构建的生命周期线路，不能冒充生产真机超时通过。

### 03/04：失败关闭

1. 先保留 `01` 的 500 行报表。
2. 导入 `03`，确认出现容量拒绝，回到 Ledger 后旧的 500 行仍在。
3. 导入 `04` 并重复同样确认。

## 内存声明边界

手工真机测试可以观察 Safari 标签页是否被系统重载、崩溃、空白或完成后无法交互。它不能产生可量化的 Worker 峰值分配值，也不能建立设备支持阈值。在尚无 Safari Web Inspector/Instruments 证据时，结果必须写为“未观察到崩溃/重载”，峰值内存仍为未测量。

## 清理和仓库检查

完成真机测试后：

1. 删除 iPhone“文件”App 中该压力包的所有副本。
2. 删除测试期间保存的全虚构 PNG。
3. 如需清理 Mac 输出，仅处理本次明确创建且不再保留的精确仓库外目录；不要删除旧验收包、归档或仓库内的 fixture。结果记录保存在包外。
4. 检查 `git status --short`，确认仓库中没有任何大 CSV、结果文件或临时包。
5. 关闭本次临时 Safari 测试标签与 Mac 局域网服务；复核 VoiceOver 和本次改动的系统权限恢复原状态，不改动无关权限。

相关真机全流程和下一轮清单见 `docs/IPHONE_SAFARI_TEST_CHECKLIST.md`；最近的历史设备证据见 `docs/IPHONE_SAFARI_EVIDENCE_2026-09-02.md`。这些 0.15 / iOS 27.0 观察不代表当前 0.19 构建已通过真机验证，也不代表支持下限 iOS/Safari 16.4 已通过。
